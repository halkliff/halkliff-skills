---
name: sharpen
description: "Improve a task's approach, framing, and verification when the user asks to sharpen it. Preserve agreed requirements and user-owned decisions."
---

Before starting, consider how a top expert would approach the task: the primary evidence they would read, the methods they would use, and an independent observation that could show the result is wrong. Identify the user's actual outcome and whether the current brief specifies too much or too little.

Improve the approach without expanding the assignment. Preserve explicit requirements, frozen baselines, and settled decisions. If changing a constraint would materially improve the outcome, explain the trade-off and leave that choice to the user; do not silently loosen it or add a new restriction.

Use the improved approach within the action the user authorized. A request to sharpen or discuss an idea does not authorize implementation, commits, publishing, new goals, or recurring work. If execution was requested, proceed with the in-scope work and keep at least one independent check of the real result. Otherwise return the improved approach and the decisions still needed. Do not substitute a rewritten prompt for the requested work.
