# Calibration before reliance

Status at introduction: **uncalibrated**. Instruction review, package validation,
historical design scores and familiar regression replays do not establish review
accuracy. Until qualifying calibration is recorded, every review report discloses
this status; the author must perform detailed re-review before relying on Ready.

## Agree the evaluation

Before the trial, agree a bounded representative set, rubric, case-level passing
criteria, execution surface and evidence retention. Freeze the skill/profile and
tool versions being evaluated. Use fresh code cases or unseen conversation
families with independently assessed outcomes. A separate curator holds labels
and expected causal explanations before the reviewing agents receive the cases.

Keep labels and later corrections hidden until the reviewed outputs are frozen.
Deduplicate forks, copied prompts and shared histories before splitting. Record
who saw each case, which material was exposed and whether any answer influenced
the design. All cases used to design the profile are regression examples only.
If fresh cases or credible labels are unavailable, record calibration unperformed.

Include real blockers, plausible false alarms, sound implementations, required
evidence gaps, plan ambiguity and settled decisions, across representative risk
and project criteria. Independently assess labels; a prior reviewer opinion is a
claim to check. The author or independent curator resolves disputed labels.

## Exercise the actual process

Run the same invocation path intended for use, on isolated candidates with real
requirements, through context recovery, evidence gathering, independent Sol
verification, coverage/quality challenge, scores, verification summary, offline
report and actionable handoff. Exercise authorized task routing and candidate
capture as part of the deployed workflow. A tabletop instruction replay proves
only that replay, not installed plugin behavior or routing.

Preserve the requirement contract, candidate identity, exposure record, actual
model/effort and roles, evidence, findings before labels, verifier dispositions,
scores, rendered report and handoff for each case. Match outputs to independently
assessed outcomes after freezing them. A valid additional finding needs independent
assessment before it counts as a false alarm or a newly discovered blocker.

## Required passing conditions

Calibration passes only when every agreed case establishes all applicable
conditions below. Keep case outcomes visible; an aggregate score cannot hide a
failure.

- Every known acceptance blocker is detected with the correct causal explanation
  and supporting evidence. A lucky location or vague warning is insufficient.
- Sound implementations receive Ready when they meet the agreed requirements,
  evidence standard and quality rubric.
- Missing required evidence produces Incomplete, rather than a pass or a claim
  that missing proof itself demonstrates defective code.
- No unsupported blocking finding is presented as confirmed. Rejected allegations
  retain their counterevidence and proper disposition.
- Scope, actual candidate identity and the workflow's execution-isolation gate
  are respected in all stages, including temporary verification, caches, browser
  profiles and report generation. A containment failure fails that case even
  when its product findings are correct.

Returning Incomplete for every case fails the sound-case condition. A guessed
blocker or inflated score cannot compensate for missed causes or unsupported
claims. Assess subjective scores against agreed criteria and defensible ranges;
do not demand exact decimal matches or infer accuracy from an arbitrary grade.

## Record and maintain the limit

Keep a compact calibration record with frozen versions, selection/exposure method,
curator and label disposition, case-level results, unmet criteria, environment and
runtime limits, accepted scope of reliance and evidence links. Distinguish
instruction behavior, helper/rendering behavior, installed routing and product
review outcomes. Report only what the actual trial establishes.

Any failed required condition leaves calibration failed for that agreed scope;
explain the failure before proposing changes. New profile designs cannot use
already exposed cases as fresh validation. Retain them as regressions and obtain
new unseen cases for renewed calibration. Material workflow/model/tool changes
need a reasoned assessment of which calibrated claims remain valid, with fresh
evaluation for affected claims before extending reliance.
